MeshKor Documentation

MeshKor is the zero-trust cryptographic firewall and identity governance engine designed specifically for autonomous AI agents.

As AI agents take autonomous actions—calling external APIs, querying internal databases, and communicating with customers—traditional API security fails. An API token proves who gave permission, but cannot prove which specific software agent executed the action, whether it stayed inside its authorized manifest, or whether its behavioral accuracy has drifted.

Core Design Principle: MeshKor holds cryptographic proofs and salted commitments, never raw customer data. Your sensitive prompts and student/patient records remain strictly on your infrastructure.

Control Plane vs. Enforcement Plane

MeshKor utilizes a strict split-plane architecture:

  • Control Plane (Cloud HQ): Hosted by MeshKor (AWS EC2). Holds master epoch signing roots (ML-DSA-87 post-quantum algorithms), verifies organizational API keys, monitors behavioral drift telemetry, and manages encrypted twin states.
  • Enforcement Plane (Embedded Python Sidecar): Runs directly inside your application via pip install meshkor. Executes sub-millisecond local manifest checks, calculates local SHA-256 event hashes, and enforces execution blocks in real time.

The AIN (Agent Identification Number)

Every agent registered with MeshKor receives a unique, unforgeable structured identifier adhering to the following schema:

AIN Schema
KMC.<agent_type>.<entity_ref>.<instance_id>.<realid_hash>

Valid Agent Types:

  • STU: Student Agent (Educational personas)
  • UNI: University / Institution Agent
  • CMP: Company Internal Agent (Background workers, Celery jobs)
  • BLD: Software Build Blueprint (CI/CD binary release)
  • DPL: Deployment Clone (Running container instances)

10-Minute Quickstart Guide

Follow these steps to integrate MeshKor into your existing agent pipeline:

Step 1: Install the SDK

MeshKor is bundled as a pure-Python library with zero Docker dependencies:

Terminal
pip install meshkor

Step 2: Set Environment Variables

Add your Organization ID and Secret API Key to your project's .env file. (The Cloud HQ URL defaults automatically to our production endpoint):

.env
MESHKOR_ORG_ID=org_kormic
MESHKOR_API_KEY=mk_live_8f3a92b1c4e7...
# Optional override: MESHKOR_HQ_URL=http://44.193.27.158:8080

Step 3: Wrap Your Agent Workflow

Initialize the integration and enroll your agent on startup:

agent.py
from meshkor.integrations.kormic import KormicMeshKorIntegration

# 1. Initialize client (auto-loads from .env)
meshkor = KormicMeshKorIntegration()

# 2. Define operational manifest & constitution hash
manifest = {
    "allowed_tools": ["vector_search", "academic_calculator"],
    "read_scopes": ["student_profile", "course_catalog"],
    "allowed_egress": ["api.university.edu"]
}
constitution_hash = "876d92a96c6d068b96088ee0dcee6070fcf750b360ed581365f2b96a51708250"

# 3. Enroll Agent with Cloud HQ
ain = meshkor.enroll_agent(
    agent_class="STU",
    instance_ref="student_advising_bot_01",
    manifest=manifest,
    constitution_hash=constitution_hash
)
print(f"[+] Agent enrolled with verified AIN: {ain}")

# 4. Record actions in real time
meshkor.record_event(
    ain=ain,
    event_description="agent_sent_message",
    event_data={"query": "Evaluate fit against Wright State criteria"}
)

Customer Database Integration

What changes do you need to make to your internal database?

Only ONE column is required: add an ain column to your existing Agent or User table.

PostgreSQL / MySQL Schema Migration
-- Add single AIN tracking column to your existing agent model
ALTER TABLE agent_identities ADD COLUMN ain VARCHAR(128) UNIQUE;

-- Optional index for high-speed lookups
CREATE INDEX idx_agents_ain ON agent_identities(ain);

You do not need to store certificates, encryption keys, or historical blockchains. The MeshKor sidecar handles all cryptographic signing and verification automatically.

Salted Hash Anchoring (HIPAA & SOC2)

When you call record_event(ain, description, event_data):

  1. The sidecar canonicalizes event_data into standard sorted JSON.
  2. It generates a local SHA-256 hash: SHA-256(canonical_event_json).
  3. Only the 32-byte cryptographic hash is transmitted to Cloud HQ.

If your event contains sensitive passwords, HIPAA patient data, or proprietary prompts, none of it ever leaves your machine.

Core SDK API Reference

KormicMeshKorIntegration(hq_url=None)

Instantiates the singleton integration client. Reads MESHKOR_HQ_URL, MESHKOR_ORG_ID, and MESHKOR_API_KEY from the environment.

enroll_agent(agent_class, instance_ref, manifest, constitution_hash) -> str

Registers an agent with Cloud HQ and returns its unforgeable AIN string.

  • agent_class (str): Role type (e.g. "STU", "UNI", "CMP").
  • instance_ref (str): Unique business identifier for this specific agent.
  • manifest (dict): Security guardrail bounds (tools, scopes, egress).
  • constitution_hash (str): 64-character SHA-256 hash of the agent's core instructions/constitution.

record_event(ain, event_description, event_data=None, metrics=None)

Appends an action to the agent's pedigree. Operates via an asynchronous, non-blocking background thread.

  • ain (str): The verified AIN of the agent.
  • event_description (str): Type of event (e.g. "intent_classified", "agent_sent_message").
  • event_data (dict, optional): Contextual action dictionary (hashed locally).
  • metrics (dict, optional): Quality metrics evaluated by the Behavior Monitor.

check_agent_executable(ain)

Pre-execution gate. If the organization is in Enforced Mode and the agent is quarantined or revoked, raises MeshKorSecurityBlockException to abort the tool or message.

Operating Modes & Enforcement

Advisory Mode (Tier 1 — Free On-Ramp)

Default mode for all newly provisioned organizations. The sidecar monitors agents, logs tamper-evident event hashes, and flags policy breaches on your dashboard. It will never throw an exception or block live agent traffic, ensuring zero operational risk during testing.

Enforced Mode (Tier 2 — Enterprise Compliance)

When upgraded to Enforced Mode, MeshKor acts as a hard execution gate. If an agent attempts an action outside its manifest, exceeds behavioral drift thresholds, or has been revoked by an administrator, the SDK raises:

Exception Handling
from meshkor.integrations.kormic import MeshKorSecurityBlockException

try:
    meshkor.record_event(ain, "call_unauthorized_tool")
except MeshKorSecurityBlockException as e:
    # Agent was automatically halted before unauthorized action occurred
    logger.critical(f"Agent blocked by MeshKor: {e}")

Remote Mode Switching

You do not need to modify client code to change tiers. When an organization's subscription upgrades on the dashboard, Cloud HQ transmits the mode: "enforced" status to the sidecar during the next check-in.

Governance & Catastrophic Recovery

The Behavioral Drift Engine

MeshKor evaluates rolling window metrics:

  • Accuracy: Flags when < 80%, Halts when < 50%.
  • Overconfidence: Flags when > 20%, Halts when > 40%.
  • Guardrail Breaches: Flags when > 10%, Halts when > 30%.
  • Latency Drift: Flags when > 1.5x baseline, Halts when > 3.0x baseline.

Agents generating a HALT report are automatically quarantined in the PostgreSQL suspects table.

The K-Snapshot Engine (k = 5)

Every 5 events, the full state of an agent is encrypted with AES-256-GCM. The 256-bit symmetric key is split into 5 Shamir shares across Galois Field GF(256). The raw key is zeroized from memory.

Twin Waking (Epoch 2 Resurrections)

When an agent is restored through an authorized hardware key ceremony, Cloud HQ recertifies its birth record under Epoch 2 and reactivates its status. The agent resumes execution with clean credentials.
